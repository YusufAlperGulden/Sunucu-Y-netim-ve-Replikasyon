Ops-Center

Manage several ClusterControl controllers from one console. Ops-Center gives you a single pane of glass to monitor and operate every controller, cluster and node.

WHEN TO ENABLE IT
  • You run more than one ClusterControl controller — for example separate prod, staging or per-region installations — and want to manage them from one place.
  • Your fleet grows beyond ~1000 nodes and you need to scale out horizontally across several CMON controllers.
  • You want centralized monitoring with the ability to switch between controllers for targeted operations.
Single-controller mode - local Learn more
Kubernetes

Deploy and manage Kubernetes-based database clusters using database operators, alongside your traditional clusters.

WHEN TO ENABLE IT
  • Your infrastructure runs on Kubernetes and you want to operate databases as native cluster resources.
  • You want database operators to automate deployment, scaling and recovery on K8s.
  • You need to manage Kubernetes-based database clusters from the same console as the rest of your fleet.

Cluster Load (OS Metrics)

Real OS metrics (CPU, RAM, Disk I/O) cannot be fetched directly from PostgreSQL (port 5432).

How to enable this:
1. SSH into your database servers as root.
2. Install Prometheus Node Exporter: sudo apt install prometheus-node-exporter
3. Start the service: sudo systemctl start prometheus-node-exporter
4. Ensure port 9100 is open in your firewall.

Once installed on your servers, this dashboard will automatically detect the OS metrics. No fake placeholder data is being drawn.

Release Notes

Use this page as your guide to stay up to date on the latest enhancements and changes, ensuring you can make the most of ClusterControl's powerful capabilities.

v1.6.0

Release cycle

We highly advise you to keep up to date with the latest version for the following reasons:

  • ClusterControl has a short release cycle compared to other software applications (likely a new major release every quarter of the year).
  • ClusterControl has to keep up with all the latest changes and modifications introduced by supported database and application vendors.
  • Some of the issues you have encountered may already be fixed in the latest weekly maintenance or major release.

What's New

  • Core Fix (Persistent Auth & Instant Nodes View Loading): Doğrudan #nodes-view veya sol menüdeki Nodes sekmesine geçildiğinde yaşanan takılma/sonsuz yüklenme (infinite loading) sorunu çözüldü. Kimlik doğrulama belirteci (globalAuthToken) kalıcı olarak localStorage ile ilişkilendirildi ve tüm direkt sayfa geçişlerinin anında yüklenmesi sağlandı.

v1.5.9

  • Visual Dynamic (Smaller & Fast-Paced Floating Particles): Giriş ekranındaki baloncuklar kompakt boyutlara (15px - 60px yarıçap) çekildi, adetleri 65'e yükseltildi ve hareket hızları artırılarak ekran üzerinde canlı, hızlı ve enerjik süzülmeleri sağlandı.

v1.5.8

  • Visual Dynamic (Extra Large & Faster Floating Bubbles): Giriş ekranındaki (Login screen) baloncuklar ekstra büyük boyutlara (180px - 460px yarıçap / 360px - 920px çap) yükseltildi ve hareket hızı ~4 kat artırılarak ekran üzerinde daha akıcı ve dinamik yüzmeleri sağlandı.

v1.5.7

  • UI/UX (Cluster Alarms Table Structure): Cluster Detay altındaki Alarms sekmesi ClusterControl ile birebir uyumlu tam tablo yapısına kavuşturuldu. "Title", "Severity", "Category", "Cluster", "Hostname", "When", "Actions" sütun başlıkları ve standart boş durum (You haven't received alarms yet. When you do, it'll show up here.) entegre edildi.

v1.5.6

  • Feature (Backups Folders & Solid White Modals): Backups sayfasına ClusterControl standardında iki klasör sekmesi eklendi: All Backups (No backups created yet.) ve Schedules (No schedules created yet.). Ayrıca yedekleme sihirbazı ve seçim pencerelerinin arka planı şeffaf/gri görünümden arındırılarak saf beyaz (solid white) kurumsal modal tasarımına dönüştürüldü.

v1.5.5

  • Visual Design (Larger Floating Bubbles): Giriş ekranındaki (Login screen) hareketli baloncuklar (floating bubbles) daha büyük, canlı ve estetik boyutlara yükseltildi (120px - 340px yarıçap). Yumuşak geçişler ve şeffaf katman efektleri uygulandı.

v1.5.4

  • Major Feature (Cluster Performance Module): ClusterControl ile birebir uyumlu Performance sekmesi entegre edildi. DB Status (Canlı durum değişkenleri karşılaştırması), DB Growth (Depolama & Hacim analitiği), DB Variables (Aranabilir konfigürasyon değişkenleri), Query Monitor (Canlı aktif SQL sorguları), Query Monitor/Agents (Ajan yönetimi), Advisors (Otomatik sağlık danışmanları), Schema Analyzer (Tablo ve sütun yapısı analizi) ve Transaction Deadlocks (Kilitlenme tespiti) alt sekmeleri aktif hale getirildi.

v1.5.3

  • Core Fix (Strict Cluster Dashboard Isolation): Sunucu Yönetim Dashboard telemetri döngüsü (fetchDashboardMetrics) tamamen yeniden yazıldı. Artık Araç Plaka Takip Sistemi açıldığında yalnızca Araç Plaka'nın 2 sunucusu; E-mail Okuma Programı açıldığında ise yalnızca E-mail Okuma Programı'nın 2 sunucusu gösterilir. Diğer tüm cluster'lara ait eski veya yabancı kartlar container'dan anında temizlenir.

v1.5.2

  • Improvement (Cluster Metric Table Dynamic Mapping): Her cluster için takip edilen ana tablo ayrıştırıldı. Araç Plaka Takip Sistemi için vehicles tablosu (6 Araç (vehicles)), E-mail Okuma Programı için ise PostgreSQL üzerindeki canlı emails tablosu (3 E-posta (emails)) otomatik sorgulanarak ekrana canlı ve doğru şekilde yansıtıldı.

v1.5.1

  • Fix (Cluster Switch & Telemetry Reset): E-mail Okuma Programı ve Araç Plaka Takip Sistemi gibi farklı cluster'lar arasında geçiş yapılırken metrik kartlarının karışması ve eski kümenin kartlarının ekranda kalması sorunu hash normalizasyonu ve tam DOM temizliği (DOM wipe & fresh reload) ile giderildi. Her cluster kendi başlığı (örn: E-MAIL OKUMA PROGRAMI) ve kendi sunucuları ile anında yüklenir.

v1.5.0

  • UI/UX (Dynamic CPU/RAM Visibility): Sunucu Yönetim Dashboard ekranında, Linux VPS / SSH yapılandırması olmayan sunucularda N/A gösteren CPU ve RAM kartları otomatik olarak tamamen gizlendi. Yalnızca gerçek SSH/OS metrikleri mevcut olduğunda kartlar görünür hale getirilir; böylece arayüz gereksiz N/A kutucuklarından arındırılmış temiz bir görünüme kavuşturuldu.

v1.4.9

  • Fix (Cluster Detail Dashboard): Belirli bir cluster'ın detay sayfasına girildiğinde (örn: Araç Plaka Takip Sistemi), diğer ilgisiz cluster'ların metrik kartlarının karışmasını önleyen filtreleme eklendi. Artık her cluster'ın Dashboard sekmesinde yalnızca o cluster'a ait sunucu düğümleri (Primary & Standby) gösterilir. Ayrıca breadcrumb navigasyonu (Project Name (ID: X)) dinamikleştirildi.

v1.4.8

  • Feature (User Management - Teams Tab): User Management ekranına Teams sekmesi tablosu eklendi. "Name", "Owner", "Created", "Actions" sütun başlıkları ve standart boş durum mesajı (No teams created yet.) eklendi.

v1.4.7

  • Fix (Cluster Detail Nodes Tab): Cluster Detay sayfasındaki Nodes sekmesinde düğüm sayısı kartlarının 0 olarak görünmesine sebep olan DOM ID çakışması giderildi (cluster-stat-*). Artık seçili cluster'a ait tüm düğümler anında Operational: 2, All: 2 vb. olarak dinamik şekilde kartlara yansıtılmaktadır.

v1.4.6

  • Improvement (Sunucu Yönetim Dashboard): Sunucu Yönetim Dashboard ekranındaki metrik biçimlendirmeleri (İşlem Yükü: 1,152,848 ✓ / 551,667 ✗, Çalışma Süresi: 6 gün, Depolama ve Bağlantılar) Araç Plaka Yönetim Sistemi formatı ile birebir uyumlu ve estetik hale getirildi. Canlı Render API doğrulaması tamamlandı.

v1.4.5

  • Fix (Sunucu Yönetim Dashboard): Backend metrik toplayıcısında (ha_manager.py) PostgreSQL veritabanı istatistiklerinin çekilmesi sırasında oluşan değişken atama hatası (NameError: tup_fetched) giderildi. Ana Sunucu (Master) ve Yedek Sunucu (Standby) için Ağ Gecikmesi (Ping: ~310ms), Depolama (9 MB), Aktif Bağlantılar, Önbellek Başarısı (%100) ve Ana Tablo Kayıtları (6 Kayıt - vehicles) gerçek zamanlı olarak bağlandı.

v1.4.4

  • UI/UX (Fixed Table of Contents): Changelog sayfasındaki sağ İçindekiler (Table of Contents) ve sol Release Notes menüleri, sayfa aşağı kaydırıldığında pozisyonunu kaybetmeyecek şekilde sabitlendi (position: sticky; top: 0). Yalnızca orta içerik alanı bağımsız kaydırılarak menülerin her zaman ekranda görünür kalması sağlandı.
  • Rules & Standards: Her commit ve güncellemede semantik sürüm numaralandırmasının (v1.4.3 → v1.4.4 → v1.4.5) otomatik artırılması kuralı devreye alındı.

v1.4.3

  • Fix (Nodes View): Nodes sayfasında düğümlerin listelenmesini engelleyen çift döngü ve eski closure referansı temizlendi. Tüm cluster'lardaki sunucular (Primary & Standby) anında stat kartlarına (Operational, Failed, Offline vb.) ve envanter tablosuna gerçek zamanlı olarak bağlandı.
  • Feature (Audit Log Search & Export): Audit Log sekmesine anlık Arama Çubuğu (Search Bar), Filtre Sıfırlama ("Clear all filters"), Yenileme (Refresh) ve ClusterControl formatında birebir uyumlu CSV Dışa Aktarma ("Export CSV") özelliği eklendi.
  • UI/UX (Loading Animation): ClusterControl tasarımı ile birebir uyumlu Circular Loading Spinner (Dönen Dairesel Animasyon) tüm tablolara, kartlara ve yükleme durumlarına eklendi. Ham metin ("Yükleniyor...") yerine zarif dönen çember animasyonu gösterilmektedir.
  • Feature (Activity Center): Activity Center ekranı orijinal ClusterControl yapısına uygun olarak 4 sekmeye ayrıldı: Alarms, Jobs (Yedekleme ve sistem işleri), Audit Log (Kullanıcı eylem ve denetim kayıtları) ve Watchlists (Beta).
  • Fix (Replication & Metrics): Frankfurt (Ana Sunucu) ve Londra (Yedek Sunucu) Neon PostgreSQL veritabanı bağlantı şifreleri ve SSL parametreleri otomatik senkronize edilerek TPS, Ping, Storage ve Ana Tablo (vehicles) kayıt sayısı canlı metrikleri bağlandı.

v1.4.2

  • Özellik 4: User Management (Kullanıcı Yönetimi) motoru aktif edildi. Veritabanı destekli User modeli oluşturuldu, şifreler bcrypt ile hash'lendi ve kullanıcı silme/ekleme işlemleri yapıldı.
  • Hotfix 3 (Final): Python AttributeError hatası çözüldü. "models.py" içerisindeki sınıf tanımına eklenmesi unutulan sütun değişkenleri (ssh_host) koda dahil edildi. Tüm özellikler %100 istikrarlı çalışıyor.
  • Hotfix 2: Internal Server Error (500) tam olarak çözüldü! Bir önceki güncellemede manuel veritabanı göçlerini yaparken tablonun adını yanlışlıkla "database_nodes" yerine "nodes" olarak sorgulayan kod düzeltildi.
  • Hotfix (500 Internal Server Error): "DatabaseNode" ve "AuditLog" tablolarındaki eksik sütunlar için otomatik SQLite / PostgreSQL şema göçü (Schema Migration) eklendi.
  • Fix: Uygulamaya yapılan önceki güncellemeler sırasında meydana gelen küçük bir yazım hatasından dolayı tüm etkileşimlerin bozulması (Syntax Error) sorunu düzeltildi.
  • Feature: "Settings" ekranında artık gerçekten var olan PostgreSQL ayarları için API bağlantıları kuruldu.

v1.4.1

  • Feature: Veritabanı gecikme (lag) ve senkronizasyon metriklerini gösteren detaylı "Sunucu Yönetim Dashboard" eklendi.
  • Improvement: Uygulama giriş (Login) ekranı kurumsal tasarıma uygun hale getirildi.
  • Fix: Uzun sayfalarda kaydırma çubuğunun (scrollbar) menülerle çakışması sorunu düzeltildi.
